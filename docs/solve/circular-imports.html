Solve · Circular dependencies

Find circular dependencies before they find you

Cycles don't announce themselves. They accrete — one convenient callback at a time — until a refactor deadlocks or an import blows up at startup. The fix is not vigilance; it's a gate that makes a cycle fail the build with the exact chain printed.

check --fail-on-cycles diff --fail-on-new-cycles call-level, not just imports

Import cycles vs call cycles — be precise. An import linter sees that module A imports B and B imports A. But an import can sit unused, and a genuine behavioral loop can thread through modules whose imports look innocent. A call-graph cycle — persist() → audit() → persist() — is a real runtime dependency loop, and that's the level this gate works at.

The demo below uses the repo fixture examples/scenarios/refactor: a service in two states, where the "after" refactor added an audit hook that quietly closed a loop. Output is verbatim.

1

The gate: one command, exact chain, exit 1

$ py-code-visualizer check examples/scenarios/refactor/after --fail-on-cycles
🔴 1 circular dependency violation(s): cycle: persist -> audit -> persist $ echo $? 1 # CI fails — with the chain, not a shrug

No spelunking: the offending loop is named. On the clean "before" state the same command prints ✅ Architecture check passed and exits 0.

2

Catch the exact PR that introduces one

Better than failing on cycles that already exist: fail only on new ones, in the pull request that creates them, with the added calls named.

$ py-code-visualizer json examples/scenarios/refactor/before -o base.json $ py-code-visualizer json examples/scenarios/refactor/after -o head.json $ py-code-visualizer diff base.json head.json --fail-on-new-cycles
### 🔴 New circular dependencies - `persist → audit → persist` ### 🔗 Added calls (2) - `persist` → `audit` - `audit` → `persist` $ echo $? 2 # the PR that closes a loop cannot merge quietly

The report renders as a PR comment (Mermaid subgraph included), so the reviewer sees the loop the moment it's born. Setup is one opt-in command: py-code-visualizer init --with gates.

Why this beats eyeballing: cycle detection runs on the parsed AST — no code executed, no dependencies installed — and output is deterministic, so the gate never flaps. When a cycle is reported, it's real, and the chain plus the file:line of every participating call is right there.
