Use case · AI agents

Feed your agent the right context

An AI agent asked to change one function doesn't need your whole repo read into its context window. It needs the verified neighborhood of its task — and nothing it has to guess. Give it exactly that: smaller, cheaper, and correct by construction.

context --focus ~96% fewer tokens 100% verified AGENTS.md

Point an agent at raw source and it re-derives the architecture on every task — inventing call relationships, missing what didn't fit the window, and paying for thousands of tokens to reconstruct facts it could have looked up. A context pack flips that: the structure is already parsed, every edge is real, and the pack is a fraction of the size.

1

Build a pack centered on the task

Name the function (or file) the agent will work on. context always includes it and its direct callers/callees, then grows to a token budget by ranking the rest of the graph with personalized PageRank — the most relevant neighbors first.

$ py-code-visualizer context . --focus persist --budget-tokens 4000
# Context Pack — yourproject - Focus: `core.persist` - Included functions: 9 (omitted 0 under budget) - Estimated size: ~365 tokens (pack) vs ~54,000 tokens (full source) ## Functions - `core.persist(record)` — core.py:7 - `service.place_order(order)` — service.py:7 … ## Verified calls (caller → callee · confidence · provenance) - `service.place_order` → `core.persist` · resolved · service.py:8 - `core.persist` → `service.audit` · resolved · core.py:9 … ## Circular dependencies touching this area - `persist → audit → persist`

Every function is real, every call edge is parsed from the AST with a file:line, and ambiguous calls are flagged rather than guessed. The agent opens the cited line only when it needs a body — the pack itself stays tiny.

2

On a small project the pack and the source are comparable. On a real one, the pack stays small while the source doesn't. Measured on a deterministic 100,000-line project, focusing on a single central function:

3

Make sure the agent actually uses it

A pack only helps if the agent reaches for it. export writes the verified graph and injects a section into AGENTS.md — the file Copilot, Cursor, and Claude Code all read automatically — telling the agent to consult the ground truth and run context for task-scoped facts.

$ py-code-visualizer export --for-ai .
Wrote ARCHITECTURE.json, ARCHITECTURE.md and AGENTS.md

Wire it into CI with py-code-visualizer export --check (via init --with context) so a PR fails if the committed ground truth goes stale — the agent always reads current facts, never yesterday's.

What you got. Your agents consume a verified, task-scoped slice of the architecture — ~96% smaller than the raw source on a large repo, with a file:line on every fact and not a single guessed edge — and an AGENTS.md that makes them reach for it by default. Point your agent at the graph, not the repo.
